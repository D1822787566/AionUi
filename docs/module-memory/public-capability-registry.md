# 公共能力平台接入

记录状态：已完成（首版）
最近更新：2026-05-04

## 模块目标

- [用户确认] 先实现一个可小范围试用的雏形：用户能够从一个由项目方维护的公共平台发现并获取 Skill 和 MCP。
- [用户确认] 公共平台必须是可维护的服务端，提供 Skill/MCP 的创建、编辑与发布能力，而不是依赖预先存在的 Registry Git 仓库。
- [用户确认] 首版不实现鉴权。
- [用户确认] AionUi 仅面向少量用户试用，先验证公共平台到客户端的获取链路。
- [用户确认] 项目面向企业内网，开发、部署和验收必须以无公网依赖的内网环境可用为准。
- [用户确认] 当前开发电脑系统时间不准确且无法修改；不得依赖本机当前时间进行验收，时间相关校验需跳过或改用可控时间源。
- [代码证据] 当前首版将“获取 MCP”限定为同步已发布的 Streamable HTTP 配置；不下载或执行本地 MCP 程序。
- [待确认] 是否在后续版本支持下载并安装本地 MCP 程序。

### PCR-D9 — 内网优先

- 状态/来源：[用户确认]
- 决策：项目以内网可用为硬性开发与验收条件，生产运行不得依赖公共互联网。
- 原因：目标使用环境是企业内网。
- 影响：资源需本地打包，依赖和制品需支持内网镜像或离线分发，服务端点需可配置为内网地址，并增加断公网核心链路验证。

### PCR-D10 — 服务端首版存储与传输边界

- 状态/来源：[代码证据]
- 决策：首版公共能力服务采用 Node.js 标准库、JSON 元数据文件和制品目录；Skill 通过 JSON 文件包接口传输，MCP 仅登记 Streamable HTTP 配置。
- 原因：`capability-platform/src/registry.mjs` 与 `src/server.mjs` 已实现且无需额外 npm 依赖，适合当前内网试用。
- 影响：可以先部署单实例并验证闭环；并发写入、数据库持久化、鉴权和 MCP 代码托管留待试用验证后演进。

### PCR-D11 — AionCore 代理内网能力平台读取

- 状态/来源：[代码证据]
- 决策：AionUi 不直接从浏览器请求能力工厂；由 AionCore 根据用户配置的 HTTP/HTTPS 内网地址读取目录和 Skill 文件包。
- 原因：桌面端与 WebUI 共用同一链路，不依赖浏览器跨域配置，也不让渲染进程直接写入本地 Skill 文件。
- 影响：公共平台首版不需要 CORS；AionCore 对 URL 协议、响应大小、包路径及 Base64 内容做边界校验，再复用本地 Skill 导入器。

### PCR-D12 — 内网服务采用绿色 EXE 部署

- 状态/来源：[用户确认]
- 决策：能力工厂首版不要求内网服务器安装 Node、Bun、Docker 或 Nginx；服务端与维护页面编译为 Windows x64 单文件 EXE，数据目录外置在 EXE 同级。
- 原因：内网 Windows 服务器不固定，迁移时需要避免重复安装运行环境。
- 影响：用户直接访问 `http://<服务器IP>:<端口>/`；迁移和备份须复制 EXE 同级 `data/`。当前无鉴权，8787 端口必须由 Windows 防火墙限至受控内网范围。

### PCR-D13 — 能力工厂源码独立同步

- 状态/来源：[用户确认]
- 决策：能力工厂源码同步至 `https://github.com/D1822787566/aionui_dg_factory.git`。
- 原因：使独立服务具备可迁移、可追踪的源码来源。

### PCR-D14 — 本地 AionCore 显式覆盖 Release 下载

- 状态/来源：[代码证据]
- 决策：设置 `AIONUI_BACKEND_LOCAL_BINARY` 时，桌面打包优先使用该本地二进制；仅在未提供本地二进制时下载 Release。
- 原因：能力工厂路由存在于本地 AionCore 0.2.2，但旧顺序会在下载成功时静默打入不含该路由的 v0.2.1。
- 影响：本地联调包可确定性包含当前 AionCore 改动；GitHub Actions run ID 仍高于单文件覆盖。

### PCR-D15 — 工作区统一记录 Windows 构建方式
